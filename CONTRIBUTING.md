# Bidra till projektet

Bidrag till christiankarlsson.xyz är välkomna. Du kan bidra genom att rapportera fel, föreslå förbättringar, förbättra dokumentationen eller bidra med kod.

## Utvecklingsprinciper

Projektet utvecklas enligt följande principer:

- Mobil först (Mobile First).
- Mastodon först.
- Utvecklat för en administrerande användare.
- Följ Unix- och GNU-filosofin: gör en sak och gör den bra.
- Prioritera enkelhet, läsbarhet och underhållbarhet.
- Undvik onödiga beroenden och komplexitet.
- Använd öppna standarder och fri programvara.

## Rapportera fel

Fel rapporteras genom Issues på GitHub.

En felrapport bör innehålla:

- En beskrivning av problemet.
- Hur problemet kan återskapas.
- Förväntat resultat.
- Faktiskt resultat.
- Relevant information om miljön där problemet uppstår.

## Föreslå förbättringar

Förslag på nya funktioner och förbättringar lämnas genom Issues på GitHub.

Beskriv vilket problem förslaget löser och hur det kan förbättra projektet.

Diskutera gärna större förändringar innan implementation påbörjas.

## Bidra med kod

1. Skapa en fork av projektet på GitHub.
2. Skapa en separat branch från `main`.
3. Genomför en avgränsad förändring.
4. Testa förändringen.
5. Dokumentera förändringen vid behov.
6. Skicka en Pull Request till projektets `main`-branch.

## Kodstandard

- Skriv enkel och begriplig kod.
- Följ projektets befintliga kodstruktur.
- Undvik orelaterade förändringar.
- Dokumentera funktionalitet där det behövs.
- Lägg aldrig till lösenord, API-nycklar eller annan känslig information.
- Läs projektets AGENTS.md och relevanta tekniska dokument.

## Utvecklingsprocess

Projektets huvudsakliga utveckling sker på Gitea. GitHub används för offentlig publicering, felrapporter, förbättringsförslag och externa kodbidrag.

Inkommande kodbidrag granskas och kan överföras till en separat utvecklingsbranch på Gitea för vidare utveckling och testning.

Godkända förändringar integreras i projektets utvecklingsbranch och publiceras därefter på GitHub genom `main`.

Ursprungliga författare ska så långt som möjligt behållas i Git-historiken.
